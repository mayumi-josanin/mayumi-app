<h1 align="center">mayumi-app — まゆみ助産院アプリ群</h1>

まゆみ助産院のお客様向け・院内向けアプリを1つにまとめたリポジトリ。
**4つのPWA＋共通の入り口** を同じドメインに置き、一度のログインで全部に入れる構成です。

**まず読むページ**

| 立場 | ページ |
|------|--------|
| お客様として**使う**人 | この下の [アクセス方法](#アクセス方法) |
| 院内で**管理する**人 | [院内向け](#院内向け) |
| **開発する**人 | **[開発者ガイド](docs/developer_guide.md)**（編集→確認→公開を1枚で） |
| **AI に手伝わせる**人 | **[CLAUDE.md](CLAUDE.md)**（絶対ルール9項目） |
| ビジリスを**触る**人 | [bijiris/CLAUDE.md](bijiris/CLAUDE.md)／[bijiris/WORK_NOTES.md](bijiris/WORK_NOTES.md) |

# お客様向け

## アクセス方法

### 開くURL

| | URL |
|---|-----|
| 📱 スマホ・🖥️ PC 共通 | **https://mayumi-josanin.github.io/mayumi-app/** |

### ログイン

| 入力欄 | 入れるもの |
|--------|-----------|
| お名前 | ご登録のお名前（フルネーム） |
| パスコード | ご自身で決めた数字 |

一度入れば **90日間** そのまま使えます。期限が切れたときだけ、もう一度お名前とパスコードを聞かれます。

### パスコードを忘れたとき

入り口の画面で「**お困りのとき**」を開いてください。

- **お名前 ＋（電話番号 または 生年月日）** が記録と一致すれば、その場で新しいパスコードを設定できます
- 電話番号も生年月日もご登録がない方は、この方法では復旧できません。**受付でお声がけください**

> [!NOTE]
> 10回続けて間違えると、10分間だけお休みになります。時間をおいてからお試しください。

### 機種変更するとき

入り口の「**お困りのとき**」→「**引き継ぎコード**」で、新しい端末へ移せます。

## 📱 iPhone の場合

1. **Safari** で https://mayumi-josanin.github.io/mayumi-app/ を開く
   （Safari 以外だとホーム画面に追加できません）
2. お名前とパスコードでログイン
3. 画面下の共有ボタン **□↑** をタップ
4. 「**ホーム画面に追加**」をタップ

ホーム画面にアイコンが追加され、普通のアプリと同じ全画面で開きます。

## 📱 Android の場合

1. **Chrome** で上記URLを開く
2. お名前とパスコードでログイン
3. 右上のメニュー **⋮** →「**アプリをインストール**」または「**ホーム画面に追加**」

## 🖥️ PC の場合

Chrome / Edge で上記URLを開き、アドレスバー右端の **インストール**（⊕）をクリックすると
デスクトップにアイコンが追加されます。

## うまくいかないとき

| 症状 | 原因と対処 |
|------|-----------|
| 画面が古いまま変わらない | ブラウザを閉じて開き直してください（PC は Ctrl+F5 / Mac は Cmd+Shift+R） |
| 「入口からお入りください」と出る | 直接アプリのURLを開いています。上のURL（入り口）から入り直してください |
| ログイン画面に戻される | 90日の期限が切れています。お名前とパスコードを入れ直してください |
| 「ログイン失敗が続いたため…」 | 10分お待ちください |
| 送信したのに反映されない | 通信状況を確認のうえ、もう一度お試しください。続くようなら受付へ |
| ホーム画面に追加できない（iPhone） | Safari で開いているか確認してください。Chrome では追加できません |

# 院内向け

管理アプリも同じ入り口から入ります。ログインすると、一覧に管理アプリが追加で表示されます。

| アプリ | できること |
|--------|-----------|
| **まゆみ助産院 管理** | 会員一覧・注文・売上集計・お知らせ配信・スタンプ調整・バックアップ確認 |
| **ビジリス 管理** | アンケート回答の確認・計測値の登録・回数券の発行と管理・AIによる回数券分析 |

### 記録の置き場所

| 何 | どこ |
|----|------|
| 会員・注文・売上 | スプレッドシート「まゆみ助産院_管理」 |

| いつ | 何 |
|------|-----|

## ログインの仕組み

```
入り口 (/start/) でログイン
  └→ GAS が札（トークン）を発行
       ├ 会員の札   … localStorage["mayumi_member_auth_token"]        90日
       ├ 管理者の札 … localStorage["mayumi_admin_auth_token"]          90日
       ├ ビジリス管理の札 … localStorage["mayumi_survey_admin_token"]   8時間
       └ ビジリスお客様 … localStorage["mayumi_survey_customer"]

4アプリは同じ origin なので、各アプリはこの札をそのまま読める
```

札の中身は `base64url({t, u, exp, sig})`、署名は `HMAC-SHA256` です。
ビジリスGASはまゆみGASと鍵が違うため、まゆみ側の `checkMemberToken` に
「この札は本物か」だけを問い合わせて、自前の札を発行し直しています。

## 反映のしかた

### フロント（画面）

```bash
# 確認用に出す
git switch develop
git push origin develop
~/mayumi-preview.command          # Tailscale で配信（Finder からダブルクリックでも可）

# 本番に出す
git switch main
git merge develop
git push origin main              # → GitHub Pages が自動で公開
```

> [!WARNING]
> 配信ファイルを変えたら **Service Worker のキャッシュ名（バージョン）を上げてください。**
> 上げ忘れると、お客様の端末に古い画面が残り続けます。
> `sw.js` / `admin/admin-sw.js` / `bijiris/*/sw.js` はそれぞれ別のスコープを持ちます。

### バックエンド（GAS）

```bash
# ビジリス … フロントとGASをまとめて反映
cd bijiris && ./deploy.sh "変更メモ"

# まゆみ … push はコマンド、デプロイはエディタから手動
cd gas && clasp push -f
#  → エディタで デプロイ > デプロイを管理 > 鉛筆 > バージョン「新バージョン」> デプロイ
#  → 「新しいデプロイ」は URL が変わるので使わない
```

> [!NOTE]
> `clasp push` しただけでは公開されません。**再デプロイまでやって初めて反映されます。**

### 確認用サーバーを立てる

```bash
caffeinate -is python3 -m http.server 8765 --bind 0.0.0.0 --directory ~/Desktop/mayumi-app
tailscale serve --bg 8765
# 止めるとき: tailscale serve --https=443 off
```

## 設計上の決めごと

| 決めごと | 理由 |
|---------|------|
| **フレームワークを使わない** | ビルド工程を持たず、`git push` だけで反映できる状態を保つため |
| **4アプリを同じ origin に置く** | localStorage を共有して、入り直しのないログインを成立させるため |
| **Service Worker はアプリごとに分ける** | スコープが分かれていないと互いのキャッシュを壊すため |
| **起動時の問い合わせは1回にまとめる** | Apps Script は同じスクリプトへの同時実行を順番待ちにする。往復の回数がそのまま待ち時間になる |
| **パスワードは平文で保存しない** | 会員ごとの塩＋SHA-256。スタッフも中身を読めない |
| **復旧は、記録にある項目だけで照合する** | 電話番号も生年月日も未登録の方を、お名前だけで通してしまわないため |
| **アンケート定義は2か所にある** | `default-surveys.js` と `gas/Code.gs`。**変更時は必ず両方そろえる** |
| **秘密情報はコードに書かない** | スクリプトプロパティ（`ADMIN_TOKEN_SECRET` ほか）で管理する |

## やってはいけないこと

- `ADMIN_TOKEN_SECRET` を変える（全員がログアウトされます）
- GAS を `clasp push` しただけで「反映済み」と言う（再デプロイが要ります）
- 「新しいデプロイ」でデプロイする（URLが変わり、全アプリがバックエンドを見失います）
- Service Worker のキャッシュ名を上げずに配信ファイルを変える
- アンケート定義を片方だけ直す
- 既存の保存項目を、断りなく変更・削除する
- `bijiris/deploy.sh` を使う（未確認の作業まで `main` へ公開されます）

# サーバー設置手順（KEM_DDENKI のPC）

まゆみ助産院のデータベース（Django + PostgreSQL）を、KEM_DDENKI が動いている
Windows PC（`desktop-rmsk0vg`）に置いて、Tailscale Funnel で公開するまでの手順。

**PCの前で作業してください。**遠隔からはできません。

所要時間の目安：①10分 ②15分 ③10分。

---

## ① PCが自分で復帰するようにする

**これを飛ばすと、停電のあと誰かがPCの前に行くまでアプリが止まります。**
いまの設定では、再起動しても**Windowsにサインインするまで Docker が起動しません**。

3つ揃って初めて意味があります。

### 1-1. 電源が戻ったら自動で起動する（BIOS）

1. PCの電源を入れた直後に `Delete` か `F2` を連打してBIOS画面に入る
2. **電源まわり**の設定の中から、次のどれかを探す
   - `Restore on AC Power Loss`
   - `AC Power Recovery`
   - `After Power Failure`
3. **`Power On`**（または `Last State`）に変える
4. 保存して終了（たいてい `F10`）

> 呼び名はメーカーによって違います。「電源」「Power」の項目を探してください。

### 1-2. Windows に自動でサインインする

1. `Win + R` → `netplwiz` と入力して Enter
2. **「ユーザーがこのコンピューターを使うには、ユーザー名とパスワードの入力が必要」のチェックを外す**
3. 「OK」→ サインインに使うアカウントのパスワードを2回入力

チェックボックスが出てこないとき（Windows 11 に多い）:

> 設定 → アカウント → サインインオプション →
> **「セキュリティ向上のため…Windows Hello サインインのみを許可する」を オフ**
> にしてから、もう一度 `netplwiz` を開く

### 1-3. スリープしない

設定 → システム → 電源 → **画面とスリープ**

- 「次の時間が経過後、デバイスをスリープ状態にする」→ **なし**

### 1-4. 鍵をかける（自動サインインの埋め合わせ）

自動サインインにすると、**PCの前に座った人は誰でもWindowsに入れます。**
顧客情報を扱うPCなので、どちらかを併せて行ってください。

- **BitLocker を有効にする**（持ち去られても中身を読めない）
- または **スクリーンセーバー設定で「再開時にログオン画面に戻る」** ＋ 待ち時間を短く

### 確認

一度PCを再起動し、**何も操作せず5分待ってから**、別の端末で開く。

```
https://desktop-rmsk0vg.tail8efe0d.ts.net/
```

KEM_DDENKI が開けば成功です。

## ② データベースを置く

PowerShell を開いて、上から順に実行します。

### 2-1. 取ってくる

```powershell
cd ~\projects
git clone https://github.com/mayumi-josanin/mayumi-app.git
cd mayumi-app\server
```

（`~\projects` は KEM_DDENKI が置いてある場所です。別の場所でも構いません）

### 2-2. 設定ファイルを作る

```powershell
Copy-Item .env.example .env
```

次に、**長いランダムな文字列を2つ**作ります。

```powershell
# これを2回実行して、出てきた文字列を控える
-join ((48..57) + (65..90) + (97..122) | Get-Random -Count 50 | % {[char]$_})
```

`.env` をメモ帳で開き、次のように埋めます。

```
DJANGO_SECRET_KEY=（1つめの文字列）
API_KEY=（2つめの文字列）
DB_PASSWORD=（適当な長い文字列）

DJANGO_ALLOWED_HOSTS=desktop-rmsk0vg.tail8efe0d.ts.net,localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=https://desktop-rmsk0vg.tail8efe0d.ts.net:10000

DB_PORT=5434
WEB_PORT=8002
```

> **`API_KEY` は、GAS だけが知っている合鍵です。**
> ここが空だと API はすべて拒否します（設定し忘れて誰でも読める状態になるのを防ぐため）。
> あとで私に伝えていただく必要があります。

### 2-3. 起動する

```powershell
docker compose up -d
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createcachetable
```

> `createcachetable` は、呼び出し回数を数えるための入れ物を作ります。
> 忘れても止まりません（数えられないときは通す作りにしてあります）が、
> 呼び出しの制限は効かなくなります。

### 2-4. 動いているか確かめる

```powershell
curl http://localhost:8002/api/health
```

`{"status": "ok"}` と返れば成功です。

> ポートは KEM_DDENKI と重ならないようにしてあります
> （KEM本番 5432/8000、KEM開発 5433/8001、まゆみ **5434/8002**）。

## ③ Funnel で公開する

**新しいノードを作る必要はありません。**（前回そうお伝えしましたが、簡単な方法があります）

Funnel が使えるポートは **443 / 8443 / 10000** の3つです。
KEM_DDENKI が 443 と 8443 を使っているので、**10000 が空いています**。

### 3-1. Funnel を有効にする

PowerShell を**管理者として実行**して、次を打ちます。

```powershell
tailscale funnel --bg --https=10000 http://127.0.0.1:8002
```

初回は「管理画面で Funnel を有効にしてください」という**リンクが表示される**ことがあります。
その場合はリンクを開き、Tailscale の管理画面で許可してから、もう一度同じコマンドを打ってください。

うまくいかない場合は、次の2段階でも同じことができます。

```powershell
tailscale serve --bg --https=10000 http://127.0.0.1:8002
tailscale funnel 10000 on
```

### 3-2. 状態を見る

```powershell
tailscale funnel status
```

`https://desktop-rmsk0vg.tail8efe0d.ts.net:10000` が出ていれば公開されています。

### 3-3. 外から届くか確かめる

**スマホのモバイル通信（Wi-Fiを切って）**から、次を開いてください。

```
https://desktop-rmsk0vg.tail8efe0d.ts.net:10000/api/health
```

`{"status": "ok"}` と表示されれば成功です。

> Tailscale が入っていない端末から見えることが大事です。
> Wi-Fi のままだと、Tailscale 経由で届いてしまい確認になりません。

### 止めたいとき

```powershell
tailscale funnel --https=10000 off
```

### 3-4. ポート番号を確かめる（アプリが直接見に行く前に）

**GASが窓口のうちは、ここは気にしなくて構いません。**
アプリが直接サーバーを見に行くようにする段階で、必要になります。

いまの公開先は末尾に `:10000` が付きます。**施設や職場のWi-Fiには、443以外のポートを
塞いでいるところがあります。**そこにいるお客様だけアプリが使えない、という形で出ます。

まず、実際に塞がれる場面があるかを確かめてください。

| 試す場所 | 開くもの |
|---------|---------|
| スマホのモバイル通信 | `https://desktop-rmsk0vg.tail8efe0d.ts.net:10000/api/health` |
| 助産院のWi-Fi | 同上 |
| よく行かれる施設のWi-Fi | 同上 |

どこかで開かなければ、443番を KEM_DDENKI と分け合う形を試します。

```powershell
# KEM_DDENKI の 443 はそのままに、/mayumi/ だけをこちらに向ける
tailscale funnel --bg --https=443 --set-path=/mayumi http://127.0.0.1:8002
```

**試したら、すぐに KEM_DDENKI が今までどおり開くか確かめてください。**
同じポートを触るので、ここだけは影響が出ないことを目で見る必要があります。
戻すときは `tailscale funnel --https=443 --set-path=/mayumi off` です。

うまくいったら、道がどう届いているかを見ます。手前で `/mayumi` が削られるのか、
そのまま来るのかで、アプリ側のURLの組み立てが変わります。

```powershell
curl -H "X-Api-Key: （.envのAPI_KEY）" https://desktop-rmsk0vg.tail8efe0d.ts.net/mayumi/api/entry-info
```

返ってきた `届いた道` を見てください。

| `届いた道` | 意味 |
|-----------|------|
| `/api/entry-info` | 手前で `/mayumi` が削られている。Django側はこのままでよい |
| `/mayumi/api/entry-info` | そのまま来ている。Django側で受ける道を合わせる |

### 3-5. 呼び出し元が1人ずつ見分けられるか

同じ `entry-info` の `見えているIP` を見ます。

| 見え方 | 意味 |
|-------|------|
| スマホから見て、自分の回線のIP | **良い。**呼び出しの制限が1人ずつ効く |
| `127.0.0.1` | Funnel が呼び出し元を伝えていない。**全員が同じ相手に見える** |

`127.0.0.1` になる場合、呼び出しの制限は「全員合わせて1分120回」として効きます。
そのままだと、混み合ったときに普通のお客様まで断られます。
そうなったら教えてください。数え方を変えます（お客様の合鍵ごとに数えるなど）。

## ③' まゆみ専用の入り口にする（③のあと、落ち着いたら）

③の形（10000番）でも動きますが、URLに `:10000` が付くため、**443以外を塞いでいる
Wi-Fi では届きません。**アプリが直接サーバーを見に行くようにする段階で効いてきます。

このPCの中に「まゆみ用の機械」をもう1台立てると、まゆみは**自分だけの443番**を
持てます。KEM_DDENKI の設定には一切触りません。

### なぜ分け合わないのか

Tailscale の公開設定は、そのPCに**1つ**しかありません。443番を KEM_DDENKI と
分け合うと、同じ設定の中に2つが同居し、**片方の作業でもう片方が落ちます。**
KEM_DDENKI 側の更新で設定を作り直すと、まゆみの分が黙って消えます。

### 3'-1. 認証キーを発行する

1. https://login.tailscale.com/admin/settings/keys を開く
2. 「Generate auth key」で1つ作る（一度きりで構いません）
3. `.env` の `TS_AUTHKEY=` に貼る

### 3'-2. 立ち上げる

```powershell
docker compose -f docker-compose.yml -f docker-compose.tailscale.yml up -d
docker compose logs tailscale
```

ログに `Success.` や `mayumi-api.tail8efe0d.ts.net` のような名前が出れば登録できています。

> 「Funnel を有効にしてください」というリンクが出たら、開いて許可してから
> `docker compose restart tailscale` を実行してください。

### 3'-3. **キーの期限切れを無効にする（忘れると180日後に止まります）**

1. https://login.tailscale.com/admin/machines を開く
2. `mayumi-api` を探す
3. 右の「…」→ **Disable key expiry**

Tailscale の機械は、既定で**180日経つと自動的に無効**になります。
そのままだと、ある日突然お客様のアプリがサーバーを見失います。
**KEM_DDENKI 側も同じ設定になっているか、ついでに確かめてください。**

### 3'-4. `.env` に新しい名前を足す

```
DJANGO_ALLOWED_HOSTS=mayumi-api.tail8efe0d.ts.net,desktop-rmsk0vg.tail8efe0d.ts.net,localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=https://mayumi-api.tail8efe0d.ts.net
```

```powershell
docker compose -f docker-compose.yml -f docker-compose.tailscale.yml up -d
```

### 3'-5. 外から届くか確かめる

**スマホのモバイル通信（Wi-Fiを切って）**から開いてください。

```
https://mayumi-api.tail8efe0d.ts.net/api/health
```

`{"status": "ok"}` が出れば成功です。**ポート番号が付いていない**ことがねらいです。

あわせて、**KEM_DDENKI が今までどおり開くか**も確かめてください
（設定は別なので影響しないはずですが、目で見て確かめます）。

### うまくいかないとき

| 症状 | 見るところ |
|------|-----------|
| `/dev/net/tun` が無いと言われる | Docker Desktop が WSL2 で動いているか |
| 再起動のたびに名前が変わる | `tailscale_state` の volume が消えていないか |
| 管理画面に `mayumi-api-1` が増えた | 覚え書きが残っていない。古い機械を消してやり直す |
| Funnel が使えないと言われる | 管理画面で Funnel を許可したか |

**だめでも③（10000番）のまま使えます。**このファイルを使わずに
`docker compose up -d` すれば元に戻ります。

## ④ 自宅に置くための備え（会員データを移す前に必ず）

自宅のPCに置くので、**止まっても誰も気づかない**のと、**PCが壊れたら中身ごと無くなる**の
2つに備えます。会員情報は作り直せません。

### 4-1. 落ちたら知らせる

まゆみのGASに入れてあります。GASのエディタで、次を順に実行してください。

| 関数 | すること |
|------|---------|
| `サーバーの生死を見る()` | いま届くかを見るだけ（メールは飛びません） |
| `見張りを始める()` | 15分おきの見張りを仕掛ける |
| `見張りを止める()` | 見張りを外す |

- 約30分止まったら **1通だけ**、直ったらもう1通だけ届きます（15分おきには鳴りません）
- 知らせ先は `josanin.mayumi@gmail.com`
- 見に行き先を変えるときは、スクリプトプロパティ `DB_HEALTH_URL`

### 4-2. 控えを毎日取る

`server\scripts\控えを取る.ps1` を、Windowsのタスクスケジューラで毎日動かします。

```powershell
# server フォルダで、まず手で1回動かして確かめる
.\scripts\控えを取る.ps1
```

うまくいったら、毎日3時に動くように登録します（**PowerShell を管理者として実行**）。

```powershell
schtasks /create /tn "まゆみDB控え" /tr "powershell -NoProfile -ExecutionPolicy Bypass -File `"$HOME\projects\mayumi-app\server\scripts\控えを取る.ps1`"" /sc daily /st 03:00 /rl highest
```

- 置き場は、Googleドライブ（パソコン版）のフォルダが見つかればそこになります。
  **見つからないとPCの中に置かれ、PCが壊れたときの備えになりません。**
  実行したときのメッセージで、どちらになったか分かります
- 14日分だけ残し、古いものは自動で消えます
- 中身が空のときはエラーで止まります（取れていないのに気づかず何日も過ぎるのを防ぐため）

### 4-3. 戻せることを一度だけ確かめる

**取れているだけでは足りません。**戻せない控えは控えではありません。

```powershell
# 中身を見るだけ（書き戻しません）
.\scripts\控えから戻す.ps1 -控え "（控えのファイル）"
```

表の一覧が出れば、その控えは使えます。実際に書き戻すのは `-本当に戻す` を付けたときだけです。

### 4-4. Windows Update の再起動時刻をずらす

設定 → Windows Update → **アクティブ時間の変更** で、院が開いている時間を指定します。
その時間内では自動再起動されなくなります。

## うまくいかないとき

| 症状 | 見るところ |
|------|-----------|
| `docker compose up` でエラー | Docker Desktop が起動しているか |
| `/api/health` が返らない | `docker compose logs web` を見る |
| Funnel の状態に何も出ない | 管理画面で Funnel を許可したか |
| スマホから届かない | `tailscale funnel status` で 10000 が出ているか |
| PCを再起動したら止まった | ①の3点が設定できているか |

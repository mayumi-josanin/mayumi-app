## 移行で直す3つのこと

### ① パスコードが平文で保存されている

いまの `パスコード` 列は **数字がそのまま入っている**（137名分）。スプレッドシートを開ける人は全員の暗証番号を読める状態。

移行時に**塩＋ハッシュに変換**する。移行スクリプトが平文を読める最後の機会なので、ここでやるのが一番きれい。

**お客様への影響はゼロ。**いまのパスコードがそのまま使え、入り直しも不要。

### ② ビジリスと会員が「お名前の文字列」で紐づいている

測定履歴の `会員番号` は 43行中 **1行しか埋まっていない**。実際の紐づけはお名前の一致頼み。
「山谷 → 山谷未央」の改名で専用スクリプトが必要になったのはこのため。

移行時に **member_id で紐づけ直す**。改名しても記録が切れなくなる。

> 移行手順: お名前で突き合わせ → 一致しないものを一覧で出す → 目で確認して割り当て。
> 42件しかないので確認は現実的。

### ③ 同じ意味の列が2つある

`最終スタンプ取得日`(126) と `最終スタンプ取得日時`(122)、`引き継ぎコード発行日時` など、
シートを継ぎ足してきた結果の重複。移行時に1本化する。

## 入り直しをゼロにするための約束

移行後も**この3つを必ず保つ**。

| | 保つもの |
|---|---|
| 1 | `ADMIN_TOKEN_SECRET` と札の形式（`base64url({t,u,exp,sig})` / HMAC-SHA256）→ 発行済みの札が通る |
| 2 | 会員ID → スタンプ・回数券・測定履歴が続く |
| 3 | 画面のURL（GitHub Pages のまま）→ ホーム画面のアイコンが生きる |

切替前に**「GASが作った札を新しい側が同じと判定するか」を実データで突き合わせる試験**を通す。
これが合わない限り切り替えない。

## 写真をどうするか

いま写真は Google ドライブにあり、シートには URL が入っている（計測写真・ビフォー/アフター）。

**当面はドライブのままにする。**DBには URL と ファイルID だけを持つ。

- 移行対象が減り、切替の risk が小さい
- 院長がドライブから直接見られる運用が変わらない
- 将来まとめて移したくなったら、URL列を差し替えるだけで済む

## 決めていただきたいこと

### A. 使っていない3つの機能を、新しい方でも作りますか

| 機能 | いまの状態 |
|------|-----------|
| **注文管理**（ショップの注文） | 表はあるが **0件**。一度も注文が入っていない |
| **サポートチャット** | 同じく **0件** |
| **お知らせテンプレート** | 同じく **0件** |

作らなければ、それだけ設計も画面もシンプルになります。あとから足すこともできます。

### B. 操作履歴（9,562行）をどこまで持っていきますか

いまは92日で自動削除されています。

- 直近92日ぶんだけ移す（推奨・軽い）
- 全部移す
- 移さない（新しい方から records し直す）

### C. アンケートの設問を、表に開きますか

- **JSONB のまま持つ**（推奨）… いまの作りに近く、設問を変えても移行不要
- surveys / questions / options の3テーブルに開く … 集計はしやすいが、設問変更のたびに面倒

### D. 最初に移すのはどちらですか

- **管理側だけ**（推奨）… 効果が大きく、患者さんに影響しない
- お客様側も同時 … 一気に終わるが、止まったときの影響が大きい

## 次にやること

上のA〜Dが決まったら、**移行スクリプトの下書き**（読み取り専用の突き合わせ）から始める。
実データを1件も変えずに「何件移せて、何件が突き合わない」だけを出せるので、
移行しない判断をしても無駄にならない。

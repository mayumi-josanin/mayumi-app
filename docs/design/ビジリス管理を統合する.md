# ビジリス管理を、アプリの管理画面に統合する

**2026-09-16。院長「ビジリスアプリに関しての管理が統合されていないので統合したい」。**

## 決めたこと（院長・2026-09-16）

- 画面は **6つ**: 集計／アンケート管理／回答管理／顧客管理／特典／回数券分析。
  設定（管理ID・パスワード）は管理画面のログインに置き換わるので作らない。追加案内はお客様側に残す。豆知識（ビジリス通信）は投稿0件なので作らない。
- データは **アプリと同じ方式**: ビジリスの GAS を窓口に残し、表ごとにサーバーへ移す（切り替えの印で戻せる）。お客様のビジリスアプリは変えない。
- **今から作り、書き込みの切り替えは 9/24 以降**（会員移行 9/19〜23 のあと）。顧客管理は会員の表を使う。

## いまの姿

```
お客様アプリ / 管理アプリ（GitHub Pages）→ ビジリスの GAS（別プロジェクト）→ ビジリスのスプレッドシート ＋ Drive（写真）＋ スクリプトプロパティ
管理アプリのログイン: 管理ID＋パスワード（GAS のプロパティ）／まゆみアプリの札でも入れる（adminLoginWithMayumi）
```

| ビジリスの置き場 | 中身 | サーバー |
|---|---|---|
| プロパティ SURVEYS_JSON | アンケートの定義（2本） | **これから**（`bijiris.Survey`） |
| シート 回答一覧 ＋ アンケートごとのシート | 回答（回答JSON・写真JSON・対応状況・管理メモ） | **これから**（`bijiris.Response`） |
| Drive Bijiris/計測時/<名前>/ | 回答の写真 | **これから**（media/bijiris/） |
| シート 測定履歴 | 計測 42件 | **済**（`measurements.Measurement`） |
| シート 回数券分析結果 ＋ TICKET_SURVEY_META/PROMPT | 回数券分析 15件・進行状況・AI の指示文 | 結果は**済**（`records.TicketAnalysis`）。メタ・指示文はこれから |
| プロパティ CUSTOMER_PROFILES_JSON / CUSTOMER_MEMOS_JSON | 顧客ごとの回数券カード・パスコード設定・メモ（**お名前が鍵**） | **これから**（`bijiris.CustomerProfile`。会員IDは自動で当てない） |
| プロパティ ADMIN_PREFERENCES_JSON | 通知メール・同意文・控え・特典（gachaPrizeConfig / milestoneRewardConfig）・分類 | **これから**（`records.AppSetting` に鍵 `bijiris_preferences`） |
| 会員データ（まゆみのシートを参照） | 顧客の一覧 | 会員の表（9/19 にサーバーへ） |
| ANTHROPIC_API_KEY | 回数券分析の AI | サーバーの .env（`ANTHROPIC_API_KEY`。院長が setkey） |

## 段取り

```
A. 表とその取り込み（今）   server/apps/bijiris のモデル・取り込み・書き出しの道具・切り替えの印（bijiris_gate）
B. 画面6つ（今）           A のあと。読むのは今から、書くのは印が立つまで断る
C. 切り替え（9/24 以降）    ビジリスの Code.gs に転送を入れる（SERVER_TABLES と同じ作り）→ clasp deploy -i → 印を立てる
```

- 書き出しは **まゆみ側の GAS に置く**（`gas/回数券分析を書き出す.js` と同じ理由: bijiris/gas を push すると未確認の変更が本番に出る恐れ。`openById` で読むだけ）。
- **お名前で会員に結びつけない**（CLAUDE.md）。顧客プロフィール・回答・回数券分析は「お名前」で持つ。会員IDは回答の会員番号や、受付が画面で結んだときだけ入る。
- 写真は Drive から取り出してサーバーの media へ（推測できない名前）。Drive の共有リンクは残さない。
- 印: `apps/manage/member_gate.py` と同じ作りの `bijiris_gate`（AppSetting `bijiris_source`＝"server"）。立つまで管理画面の書き込みは断る。

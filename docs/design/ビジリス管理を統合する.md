# ビジリス管理を、アプリの管理画面に統合する

**2026-09-16。院長「ビジリスアプリに関しての管理が統合されていないので統合したい」。**

## 決めたこと（院長・2026-09-16）

- 画面は **6つ**: 集計／アンケート管理／回答管理／顧客管理／特典／回数券分析。
  設定（管理ID・パスワード）は管理画面のログインに置き換わるので作らない。追加案内はお客様側に残す。豆知識（ビジリス通信）は投稿0件なので作らない。
- データは **アプリと同じ方式**: ビジリスの GAS を窓口に残し、表ごとにサーバーへ移す（切り替えの印で戻せる）。お客様のビジリスアプリは変えない。
- **今から作り、書き込みの切り替えは 9/24 以降**（会員移行 9/19〜23 のあと）。顧客管理は会員の表を使う。

```

B. 画面6つ（今）           A のあと。読むのは今から、書くのは印が立つまで断る
C. 切り替え（9/24 以降）    ビジリスの Code.gs に転送を入れる（SERVER_TABLES と同じ作り）→ clasp deploy -i → 印を立てる
```

- 書き出しは **まゆみ側の GAS に置く**（`gas/回数券分析を書き出す.js` と同じ理由: bijiris/gas を push すると未確認の変更が本番に出る恐れ。`openById` で読むだけ）。
- **お名前で会員に結びつけない**（CLAUDE.md）。顧客プロフィール・回答・回数券分析は「お名前」で持つ。会員IDは回答の会員番号や、受付が画面で結んだときだけ入る。
- 写真は Drive から取り出してサーバーの media へ（推測できない名前）。Drive の共有リンクは残さない。
- 印: `apps/manage/member_gate.py` と同じ作りの `bijiris_gate`（AppSetting `bijiris_source`＝"server"）。立つまで管理画面の書き込みは断る。

Code.gs を読んで分かったこと:
- **「読む関数」が書く。**`loadSurveys_` `getPreferences_` `getCustomerProfiles_` `getCustomerMemos_` は正規化した結果が元と違えばプロパティへ書き戻す（`getCustomerProfiles_` は会員番号の採番まで）。写しを取るときは `getProperty` で生のまま読む。
- **ゴミ箱は列ではなく対応状況** `status="trash"`。`getResponses_` は `includeTrashed` が無いと落とす。
- **写真は 2026-08-25 からリンク共有をやめている**（`savePhotoFiles_`）。`https://drive.google.com/uc?id=` では取れないことがある。取れなければ院長のアカウントで Drive から落として `--写真フォルダ` で入れる。Drive のリンク（url / previewUrl / thumbnailUrl…）はサーバーに持たない。
- 写真の種別は `measureTimingOf_` と同じ判定（計測時アンケートは「計測のタイミング」の回答で before / after、旧設問は ID で決まる）。
- 顧客プロフィールの `memberNumber` は **GAS がまゆみの会員データを氏名で引いた結果**（`まゆみ会員_対応表_`）。写すだけで `member_id` には入れない。
- パスコードのハッシュはビジリス GAS の TOKEN_SECRET を混ぜている（`hashPasscode_`）。サーバーでは照合できない。
- Code.gs の `SPREADSHEET_ID` は `1oDNT…` だが、実際に動いているのはプロパティ `ACTIVE_SPREADSHEET_ID` の `1pONQ…`（回数券分析の書き出しと同じ ID を使っている）。

### 書き出しと取り込みの手順

```
【まゆみの GAS】 ビジリスの回答を書き出す()            → ビジリス回答_*.json
【ビジリスの GAS】ビジリスのアンケート定義を書き出す()  → ビジリスアンケート_*.json   ※ gas/ビジリスを書き出す.js を bijiris/gas/ に写して実行
【ビジリスの GAS】ビジリスの顧客プロフィールを書き出す() → ビジリス顧客_*.json
【ビジリスの GAS】ビジリスの設定を書き出す()            → ビジリス設定_*.json（秘密は出さない）

cd server
python manage.py ビジリスのアンケートを取り込む ビジリスアンケート_*.json --下見   → 外して本番
python manage.py ビジリスの回答を取り込む ビジリス回答_*.json --下見              → 外して本番。写真は --写真 [--写真フォルダ DIR]
python manage.py ビジリスの顧客を取り込む ビジリス顧客_*.json --下見
python manage.py ビジリスの設定を取り込む ビジリス設定_*.json --下見
python manage.py ビジリスを突き合わせる ビジリス回答_*.json                       （読むだけ）
python manage.py 回数券分析を取り込む 回数券分析_*.json                            （既存）
```

順番はアンケート → 回答（回答は `survey_key` でアンケートに結ぶ）。どれも何度流しても増えない。
書き出した JSON は取り込みが済んだら `書き出しJSONを片付ける()`（ビジリスの GAS で出したものは、そのアカウントの Drive で消す）。

### 院長に頼むこと

1. **bijiris/gas に読むだけの道具を置く許可。**`gas/ビジリスを書き出す.js` を `bijiris/gas/` へ写して `clasp push`（deploy は不要）。push すると Code.gs の未確認の変更も一緒に本番へ出るので、先に `bijiris/WORK_NOTES.md` の「未反映」を確かめる。
2. 3つの書き出し（アンケート定義・顧客プロフィール・設定）をビジリスの GAS のエディタから実行し、JSON をサーバーへ。
3. 写真が `--写真` で取れなければ、Drive の `Bijiris/計測時/<お名前>/` などから **ファイルIDを名前にして**落とし、`--写真フォルダ` で入れる（枚数は回答の書き出しのログに出る。2026-08 時点でのべ49枚）。
4. `ANTHROPIC_API_KEY` はサーバーの `.env` へ（setkey）。JSON には出さない。
5. 9/24 以降: Code.gs に転送を入れて `clasp deploy -i` → `ビジリスの正を切り替える server`。

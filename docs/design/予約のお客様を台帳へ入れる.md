# 予約のお客様を台帳へ入れる

**2026-09-08 の設計。**院長のご要望はこうだった。

> 予約システムで入力されたお客様情報は会員情報シートに登録されますか？
> 新規のお客さんが予約を行った場合。来院してアプリを登録したら、
> 入力されていない他の項目について追加入力されますか？

**答えは「いまはつながっていない。9/19のあとにつなぐ」。**
形は [お客様台帳を1つにする](お客様台帳を1つにする.md)、
IDの集め方は [LINEとつなぐ](LINEとつなぐ.md)。

---

## いまどうなっているか

```
ご予約         →  booking.Customer に1件
                  氏名・フリガナ・電話・生年月日・住所・LINEID

来院・アプリ登録 →  会員シートに**別の行**が1件

                  **同じ方が2か所に、別々に。**
```

予約システムのコードに、会員シートを呼ぶ口は**1つもない**（2026-09-08 確認）。

### なぜ 9/19 を待つのか

**技術的には待たなくても作れる。**GASに会員を書く窓口があるので、
予約システムからそこへ投げればシートに行は作れる。**それでもやらない。**

```
① 同時に書くと壊れる
   registerAccount は**全行を読んでから書く。鍵（LockService）が無い。**
   GAS全体で LockService を使っているのは1か所だけ（ガチャの抽選）。
   会員番号は MYM- ＋ 乱数4桁で、読んだ全行と衝突しないか見るだけ。
   **書き手がアプリ1つだから、いままで問題が出ていない。**
   予約システムを足すと書き手が2つになる。エラーは出ず、
   あとで「記録が消えている」として表に出る。

② 11日後に捨てる作業になる

③ 予約の完了画面が、シートへの書き込み（数秒）を待つ
```

**待っても何も失われない。**booking.Customer が必要な項目を全部持っている。
9/19のあとにまとめて取り込める。

---

## 作るものは3つ

### ① 初回の取り込み（1回だけ）

`booking.Customer` を台帳へ。**照合はこの順で、上から。**

```
1. LINEユーザーIDが一致          → 結ぶ（確実）
2. 氏名＋生年月日が一致           → 結ぶ
3. 氏名＋電話が一致              → 結ぶ
4. どれも一致しない              → 新しく作る（登録経路＝予約システム）
```

**2〜3で候補が2人以上出たら、結ばない・作らない。**保留にして受付が見る。
`registerAccount` が「同じお名前で生年月日が無い方がいる」ときに
受付へ回しているのと同じ考え方。**機械が決めると、間違いに誰も気づけない。**

作る行に入れるもの:

```
会員ID       採番する（既存と衝突しないこと）
氏名・フリガナ・電話・生年月日・住所・LINEユーザーID
登録経路      予約システム
メモ          「予約システムから取り込み（2026-09-xx）」
パスコード     **空。**その方はまだアプリにログインできない
```

### ② これから予約が入るたびに、台帳へ1行

予約システム → 台帳の窓口（サーバー同士）。

**台帳に書けなくても、ご予約は成立させる。**
予約そのものの正は予約システムなので、台帳は後から追いつける
（booking.Customer に全部残っている）。
知らせが飛ばないことより、ご予約が失敗するほうが困る──
`notify_clinic_email` と同じ考え方。

### ③ アプリ登録が、その行を見つける

`registerAccount`（`gas/管理者・お客様.js` 2337行）は**すでに
「空いている欄だけ埋める」作りになっている。**作り直しではなく、
探し方を1つ足すだけ。

```
いま    氏名＋生年月日
足す    LINEユーザーID（アプリでLINEをつないだ方）
残す    「同じ氏名で生年月日が無い行がある」→ 受付へ
```

**残す分岐が安全網。**予約から作った行には生年月日が入るので、
ここに落ちる方は減る。ゼロにはしない。

## 危ないところ

**① 予約なさった方と、施術を受ける方が違うことがある。**

ポチコのフォームに「ビジリスをご利用になる方のお名前」「参加される方の
お名前」という設問が実在した（569件・252件）。**代理のご予約がある。**

LINEユーザーIDは**ご予約なさった方**のもの。受ける方のものではない。
機械的に結ぶと、お母様の会員に娘さんのご予約が付く。

> **確かめること: 予約フォームの「お名前」は、受ける方か、予約した方か。**
> ほとんど同じだが、違う場合の扱いを決める必要がある。

**② LINEユーザーIDは unique。**
間違えて別の方に入れると、**本当のご本人がつなげなくなる。**
気づくのは、その方が「つながりません」とおっしゃったとき。

**③ 受付での代理登録には LINEID が無い。**
ポチコの予約3,412件のうち**823件**がそれだった。同じことが起きる。

**④ 会員番号の空きが減る。**
`MYM-` ＋ 乱数4桁は9,000通り。いま164名。取り込みで約360名になる。
まだ余裕はあるが、**採番のやり方は一度見直す価値がある。**

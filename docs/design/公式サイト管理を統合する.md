**2026-09-15。院長の指示「公式サイトの管理も統合したい。今までと同じく」。**
今までと同じく＝**画面の中身は今のサイト管理アプリ（mayumi-site/admin/app.py）と全く同じ、見た目は KEM 風。**

## 決めたこと（2026-09-15・院長）

- **公開先は GitHub Pages に切り替える**（docs/切替当日の手順書.md の計画どおり）。
  管理画面の「公開」は「GitHub の main に送る」だけで済む。FTP の秘密は要らない。
- **今から着手**（9/19 の前）。サーバーへ載せるのは 9/19 の後でもよい。

## 作り

```
Django 管理画面（server/apps/hp）
   └ mayumi-site のリポジトリを1つ置き（サーバーPC: ~/projects/mayumi-site-draft → 箱の /site）、
     その admin/*.py（core / news / blog / classroom / layout / calendar_block / release / gitops）を
     **そのまま呼ぶ**（apps/hp/repo.py）。作り方を二重に持たない。
   └ app.py にしか無い3つ（publish_everything / restore_backup / 公開の2段階）だけ actions.py に写した
```

- 設定: `SITE_REPO_DIR`（箱では /site）、`SITE_GIT_TOKEN`（GitHub の fine-grained token、mayumi-site の Contents: Read and write。
  院長が `setkey.ps1 SITE_GIT_TOKEN <値>` で入れる。**値は誰にも見せない**）。鍵は git の環境変数で渡し .git/config には書かない。
- 箱に git を入れた（Dockerfile）。docker-compose で `../../mayumi-site-draft` を `/site` に載せる。
- 画面は同じログイン（まゆみ）・同じ左メニューの「公式サイト」の段。
- 試験は mayumi-site の写しを一時フォルダに作って行う（tests/conftest.py `site_repo`。手元に mayumi-site が無ければ飛ばす）。
  写しでは「【下書き】」の印を外す（本物には20件残っていて、公開前の点検がそこで止まる。それは正しい動き）。

## 画面（旧アプリの NAV の順）

| 画面 | 旧アプリ | Django |
|---|---|---|
| 🏥 基本情報（診療時間・料金表・SNS・ブログの見出し・ページの頭・資料） | sec_basic_page | 作る |
| 📢 お知らせ（＋アプリの NEWS から取り込み） | sec_news | 作る（取り込みはサーバーの表から直接） |
| ✍️ まゆみのつぶやき | sec_blog | 作る |
| 🎒 各種お教室 | sec_classes | 作る |
| 📅 診療カレンダー（＋アプリのカレンダーから取り込み） | sec_closed | 作る |
| 🎛️ 選択肢の設定 | sec_options | 作る |
| 🖼️ 写真 | sec_images | 作る |
| 🧩 ページの編集 | sec_layout | 作る |
| 👀 プレビュー | sec_preview | **済（9/15）** |
| 🌐 公開する | sec_publish | **済（9/15）** |
| 🔗 保存の記録 | sec_git | **済（9/15）** |

旧アプリは全画面を1枚の HTML に置き、「手元に反映」で編集中の全部を content.json に保存してから HTML に書き込む。
Django では**画面ごとに content.json の該当部分を保存**し、「公開する」の確認用で HTML に書き込む（順番は同じ）。

## 切り替えたあと

- Mac のサイト管理アプリは使わない（2か所で編集すると食い違う。「保存の記録」の「GitHubから受け取る」で合わせられるが、避ける）。
- GitHub Pages への切り替え（DNS・Cloudflare）は docs/切替当日の手順書.md のとおり別途。

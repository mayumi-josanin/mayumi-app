# 予約システム設計 — ポチコから自作へ

いまお使いのポチコをやめて、**アプリと LINE から予約できる仕組みを自分たちで持つ**ための設計。
**まだ決めていない項目は最後の「決めていただきたいこと」にまとめてある。**

- 前提: 施術するのは**まゆみさん1人**。同じ時間に2件は入らない。
- 方針: **同じ時間に2件入ることが、仕組みとして起きないようにする**。

---

## いま何が困っているか

ポチコは「メニューごとに枠を用意する」作りで、**担当者という考え方がない**。
そのため、Aメニューの 10:00 と Bメニューの 10:00 が別々に埋まり、同じ時間に2件入ってしまう。
設定を工夫しても直らない。作りの問題なので、乗り換えるか作り直すしかない。

## 設計の芯

> **予約枠を持つのはメニューではない。まゆみさん本人の「1本の時間軸」だけが枠を持つ。**
> メニューは「何分かかるか」を決めるだけ。

これさえ守れば、メニューが何個に増えても二重予約は起きない。
お客様の見え方はホットペッパービューティーと同じで、

1. メニューを選ぶ
2. **そのメニューが収まる空き時間だけ**がカレンダーに出る
3. 時間を選んで確定

---

## 何が空き時間を埋めるか

空き時間 ＝ 営業時間 −（① 既に入っている予約 ＋ ② 休診・往診などの予定 ＋ ③ 受付の締切）

| | 元 | いまの状態 |
|---|---|---|
| ① 予約 | **新しく作る「予約」シート** | まだ無い |
| ② 休診・往診・訪問産後ケア・教室 | 既存の **カレンダーシート** | **時刻が構造化されていない**（後述） |
| ③ 締切・営業時間 | **新しく作る「予約設定」シート** | まだ無い |

### ② の注意 — カレンダーシートは今のままでは使えない

カレンダーシートの列は
`日付 / イベント名 / 詳細 / カラー / 公開設定 / 画像URL / 更新日時`
で、**時刻は「詳細」欄に文章で書かれている**（例：`10:00〜11:30 定員5名様`）。
文章から時刻を推測して予約を止めるのは危険なので、列を足して機械が読める形にする。

追加する列:

| 列 | 例 | なぜ |
|---|---|---|
| `開始時刻` | `10:00` | 空欄なら終日として扱う |
| `終了時刻` | `11:30` | 同上 |
| `予約ブロック` | `終日止める` / `この時間だけ止める` / `止めない` | 「お灸イベントの告知」のように、**載せたいだけで予約は止めたくない**ものがあるため |

既存の 116 件は `止めない` を初期値にし、休診日だけ `終日止める` に直す。
**初期値を「止める」にすると、過去の告知が全部予約をふさいで大事故になる。**

## 足すもの・作るもの

### MENUS シートに足す列

いまは `登録日 / メニュー名 / 画像URL / 概要説明 / 予約状況 / 公開設定 / 更新日時 / カテゴリ / 表示順`。

| 追加する列 | 例 | 備考 |
|---|---|---|
| `所要時間（分）` | `60` | これが無いと空き枠が計算できない。**必須** |
| `前バッファ（分）` | `0` | 準備が要るメニューだけ |
| `後バッファ（分）` | `10` | 片付け・記録の時間 |
| `料金` | `5,000` | 表示用。決済はしない |

既存の `予約状況`（`予約受付中` / `予約対象外`）は**そのまま使う**。
`予約対象外` のメニューは予約画面に出さない。

### 新しいシート「予約」

| 列 | 例 | 備考 |
|---|---|---|
| 予約ID | `RSV-20260901-0001` | 行番号は使わない。並べ替えで壊れるため |
| 受付日時 | | |
| 会員ID | `MYM-0123` | **お名前では紐づけない**（同姓同名で混ざった事故があるため） |
| お名前 | | 表示用 |
| 電話番号 | | 当日の連絡用 |
| メニュー行 | `5` | カレンダーと同じく行番号で持つ。名前を変えても切れない |
| メニュー名 | | 表示用（当時の名前を残す） |
| 日付 | `2026-09-01` | |
| 開始 / 終了 | `10:00` / `11:10` | **バッファ込みの占有時間**。お客様に見せるのは施術時間だけ |
| 状態 | `確定` / `キャンセル` / `来院済み` / `無断キャンセル` | |
| ご要望 | | 自由記入 |
| 変更日時 / キャンセル日時 | | |
| 通知の送信記録 | | 二重送信を防ぐ |

### 新しいシート「予約設定」

曜日ごとの営業時間（午前・午後の2本持てる形）と、受付単位・何日先まで・締切・当日キャンセルの可否。
**GAS のコードに直接書かない。**まゆみさんが自分で変えられないと、季節ごとに毎回こちらへ依頼が来る。

## 二重予約を防ぐ（ここが本体）

お客様2人が同じ瞬間に同じ時間を押す可能性がある。表示上の空きは信用しない。

```
確定処理:
  1. LockService.getScriptLock().waitLock(20秒)   ← 処理を1件ずつに直列化
  2. 予約シートを読み直し、その時間が本当に空いているか確認   ← ここが要
  3. 空いていれば追記。埋まっていれば「たった今埋まりました」と返す
  4. ロック解放
```

**2 を省くと、画面に空きが出ていた瞬間の情報で書き込んでしまい、二重予約になる。**
`LockService` は既にこのファイル内で使っている（`gas/管理者・お客様.js` 7547行付近）ので、同じ書き方に揃える。

将来 `server/`（Django + PostgreSQL）へ移したときは、
`EXCLUDE` 制約と `tstzrange` を使えば**データベース自体が重複を拒否する**ようにできる。
そちらが本命だが、いまは GAS で成立させる。

## 画面

### お客様アプリ（既存の mayumi-app に足す）

- メニューを選ぶ → 日付を選ぶ → 空いている時刻だけがボタンで並ぶ → 確認 → 完了
- マイページに「次のご予約」と、変更・キャンセルのボタン
- **空き枠は毎回サーバーに聞く。**端末にキャッシュしない（古い空きを見せると二重予約になる）

### 管理者アプリ（既存の admin/ に足す）

- 今日・今週の予約一覧
- 電話予約をまゆみさんが代わりに入れる画面（**これが無いと運用できない**）
- 臨時の予定でブロックする（カレンダーシートに書くのと同じこと）
- キャンセル・来院済みの記録

## LINE との統合

段階を分ける。**最初から全部やらない。**

| 段階 | やること | 効果 |
|---|---|---|
| 1 | LINE公式アカウントのリッチメニューから、アプリの予約画面を開く | これだけでポチコを止められる |
| 2 | LIFF 化して LINE ログイン → 会員と紐付け | お名前の入力が不要になる |
| 3 | Messaging API で確定通知・前日リマインド | 忘れ防止 |

**通知は LINE に寄せない。**
LINE の push は無料枠（月あたりの通数）を消費し、リマインドで簡単に使い切る。
このアプリには既に OneSignal のプッシュ通知があるので、
**確定通知・リマインドはアプリのプッシュとメール、LINE は入口だけ**にするのが安く確実。

---

## ポチコからの切り替え

- **並行稼働はしない。**両方から同じ時間が取れてしまい、二重予約の原因が増えるだけ。
- 切替日を決め、その日にポチコの受付を止める。
- ポチコに入っている先の予約は、管理画面から手で入れ直す。件数を先に数えておく。
- 切替の1〜2週間前から LINE とアプリでお知らせする。

## 初版では作らないもの

理由を書いておく。あとで「なぜ無いのか」を思い出せるように。

| | 理由 |
|---|---|
| 複数スタッフ・複数リソース | 1人しかいない。作ると空き枠の計算が一気に難しくなる |
| オンライン決済 | 現地でのお支払いが続くため |
| 回数券・スタンプとの自動連動 | 予約が安定してからでよい。先に繋ぐと予約側の修正が怖くなる |
| キャンセル待ち | 運用が固まってから |
| Googleカレンダーへの書き出し | 「どちらが正か」が曖昧になると二重予約の温床になる。必要なら**読み取り専用の写し**として後で足す |

## 決めていただきたいこと

これが決まらないと空き枠を1つも計算できない、という順に並べてある。

### A. 営業時間

- 曜日ごとに何時から何時まで施術を受けるか
- 昼休みはあるか（例：12:00〜14:00 は入れない）
- 定休日はあるか

### B. メニューごとの所要時間

- 各メニューの施術時間（分）
- 片付け・記録に何分要るか（全メニュー共通でよければ1つの数字で）

### C. 受付のルール

| 項目 | 仮の案 | |
|---|---|---|
| 予約の刻み | 15分単位 | 30分単位のほうが管理は楽 |
| 何日先まで受けるか | 60日先まで | |
| いつまで受けるか | 前日 21:00 まで | 「3時間前まで」等でも可 |
| お客様のキャンセル | 前日まではアプリから、当日は LINE で連絡 | |
| 確定の仕方 | **申し込んだ時点で確定** | 「まゆみさんが承認して確定」にもできる。承認制は確実だが、返事するまでお客様が待つ |

### D. 誰が予約できるか

- 会員登録した方だけか、会員でなくても取れるか
- 初回の方に聞いておきたいこと（ご相談内容・出産予定日・お子様の月齢など）

### E. 産後ケア・往診の扱い

- これらもアプリから予約を受けるのか、いままで通り LINE での相談から入るのか
- 往診は移動時間があるはずなので、**前後にどれだけ空けるか**

---

## 進める順番

1. **A〜E を決める**（ここが全部の前提）
2. シートの列を足す（MENUS・カレンダー・予約・予約設定）
3. GAS に空き枠の計算と確定処理（ロック付き）を書く
4. 管理者アプリに予約一覧と代理入力 ← **お客様に出す前にこちらを先に**
5. お客様アプリに予約画面
6. 身内で1〜2週間試す（実際に予約を入れてみる）
7. ポチコ停止・切り替え
8. LIFF 化・リマインド

**4 を 5 より先にやる。**お客様側だけ先に出すと、電話予約が入ったときに止める手段が無く、二重予約になる。

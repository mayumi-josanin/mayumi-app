# 切り替えの段取り

GAS からサーバー（自宅PCの Django + PostgreSQL）へ、お客様アプリの
通信先を切り替えるための手順書。**2026-08-23 時点。**

切り替えるのは**1行だけ**。

    app.js 3行目
    const GAS_URL = 'https://script.google.com/macros/s/AKfycbzf3iBS.../exec';
                 ↓
    const GAS_URL = 'https://mayumi-api.tail8efe0d.ts.net/api';

**だからこそ、戻すのも1行。**ここが唯一の切替点であることを確かめてある。

---

## 1. 切り替える前に、必ず済ませること

### ① 会員データを、切り替え直前にもう一度移す

**取り込みは1回で終わらない。**2026-08-18 に153名を移したが、
8月23日には**157名**になっていた。5日で4名増えている。

    GASで  会員データを書き出す()          → ダウンロード
    PCで   python manage.py 会員を取り込む 会員データ.json --下見
           （差分を確かめて）--下見 を外す

**このJSONにはパスコードが平文で入っている。**取り込んだら必ず消す。

### ② 会員ごとの印を移す

    GASで  会員ごとの印を書き出す()        → ダウンロード
    PCで   python manage.py 会員ごとの印を取り込む 会員ごとの印.json --下見

2026-08-23 時点で**2名分**（アンケート回答とお礼スタンプ）。
移し忘れると、その2名に**お礼スタンプが二重に付く。**

### ③ 控えを取る

    docker compose exec -T db pg_dump -U postgres -Fc mayumi > backups/切替前.dump

**スプレッドシートのコピーも作る。**（GASは触らないが、戻すときの拠り所）

### ④ サーバーが動いていることを、外から確かめる

    curl "https://mayumi-api.tail8efe0d.ts.net/api?action=getNews"

**合鍵なしで通ること。**お客様アプリは合鍵を送らない。

---

## 2. いつ切り替えるか

**水曜か日曜の深夜2時〜3時。**

理由: 端末の記録（`lastSeenAt`）を数えると、この時間帯が最も静か。
93日の記録で、深夜2時台にアプリを開いた方はごく少ない。

**受付が開いている時間には切り替えない。**
スタンプを入れている最中に切り替わると、記録が片方にしか残らない。

---

## 3. 切り替えの手順

1. `app.js` の `GAS_URL` を書き換える
2. **`sw.js` のキャッシュ名を上げる**（上げないと古い画面が残る）
3. **`index.html` の `?v=` も上げる**（両方上げないと片方が古いまま）
4. `develop` で確認 → `main` へマージ → push
5. GitHub Pages に出るのを待つ（数分）
6. 自分の端末で開いて、次を確かめる

### 切り替え直後に確かめること

| 見るところ | 期待 |
|---|---|
| お知らせ | 88件出る |
| 商品 | 8件出る |
| カレンダー | 120件出る |
| メニュー | 10件出る |
| スタンプ | **自分の数が変わっていない** |
| 通知の設定 | 入切が変わっていない |
| 「お困りのとき」 | 候補が出る（お名前は伏せ字） |

**スタンプが0になっていたら、すぐ戻す。**

---

## 4. 戻し方（**何より先に決めておく**）

### 5分で戻る

1. `app.js` の `GAS_URL` を元に戻す
2. `sw.js` と `index.html` の版数を**さらに上げる**（下げない）
3. push → GitHub Pages に出るのを待つ

**版数は下げない。**下げると、新しいほうを掴んだ端末が更新されない。

### 戻したあとに要る作業

切り替えていた間にサーバーへ書かれたぶんは、**スプレッドシートに無い。**

    ・端末の記録合わせ … 消えてよい（次に開けば書き直される）
    ・スタンプの同期   … 消えてよい（端末側にも残っている）
    ・**新規登録**     … **消えてはいけない**
    ・**復元・パスコード再設定** … **消えてはいけない**

戻したら、サーバーの `操作履歴` と `会員` の**行番号が空の行**を見て、
その間に起きたことを手でスプレッドシートへ写す。

    行番号が空 ＝ サーバーが自分で作った記録

**切り替えている時間が短いほど、この作業は軽い。**

---

## 5. 承知しておくこと

### 合鍵は求めない（GASと同じ）

**お客様アプリは合鍵を1つも送っていない。**GASのWebアプリが
「全員に公開」で動いているため。サーバーも同じ一覧
（`公開アクション`）を持ち、そこに載っているものは通す。

**GASの前にはGoogleの設備があるが、自宅のPCには無い。**
切り替え後しばらくは、当たり方を見張る。

### 入れてある守り

| | |
|---|---|
| 復元の回数制限 | 10回/10分・**お名前ごと**（全体で止めない） |
| 数える場所 | データベース（処理が3つ並んでも効く） |
| パスコード | **ハッシュで保存**（GASは平文） |
| 新規作成 | **お名前が無ければ作らない**（GASは作る） |
| 復元の候補 | 生年月日・電話番号は**返さない**・お名前は伏せる |

### GAS側に残っている穴

**`updateUser` は、お名前なしで空の会員を作れる。**合鍵なしで誰でも呼べる。
サーバー側は塞いだが、**切り替えるまではGASが受け続ける。**

塞ぐなら `gas/管理者・お客様.js` に1行足して `clasp push` ＋ **デプロイ**。
（デプロイは必ず `-i <デプロイID>`。付けないとURLが変わる）

---

## 6. 切り替えたあと

- 数日は、毎日 `会員数` と `操作履歴` を見る
- スプレッドシートは**しばらく消さない**（戻れる状態を残す）
- 落ち着いたら、GAS側の書き込みを止める（読み取りだけにする）

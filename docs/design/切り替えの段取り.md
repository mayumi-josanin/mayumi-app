切り替えるのは**1行だけ**。

    app.js 3行目
    const GAS_URL = 'https://script.google.com/macros/s/AKfycbzf3iBS.../exec';
                 ↓
    const GAS_URL = 'https://mayumi-api.tail8efe0d.ts.net/api';

**だからこそ、戻すのも1行。**ここが唯一の切替点であることを確かめてある。

## 1. 切り替える前に、必ず済ませること

### ① 会員データを、切り替え直前にもう一度移す

**取り込みは1回で終わらない。**2026-08-18 に153名を移したが、
8月23日には**157名**になっていた。5日で4名増えている。

    GASで  会員データを書き出す()          → ダウンロード
    PCで   python manage.py 会員を取り込む 会員データ.json --下見
           （差分を確かめて）--下見 を外す

**このJSONにはパスコードが平文で入っている。**取り込んだら必ず消す。

### ② 会員ごとの印を移す

    GASで  会員ごとの印を書き出す()        → ダウンロード
    PCで   python manage.py 会員ごとの印を取り込む 会員ごとの印.json --下見

2026-08-23 時点で**2名分**（アンケート回答とお礼スタンプ）。
移し忘れると、その2名に**お礼スタンプが二重に付く。**

### ③ パスコードの点検（**当日にもう一度**）

2026-08-27 に36件を直したが、**その後に登録された方でまた起きうる**。
書式は自動で整うようにしたが、**念のため当日に数える。**

    GASで  パスコードの下見()   … 「短くなっている」が 0名 であることを確かめる
           0名でなければ パスコードの0を戻す()

**表を直してから取り込むこと。**順番を逆にすると、古いハッシュが残る。
（取り込み側は、平文と合わなければハッシュを入れ直すようにしてある）

> **なぜ大事か**: GAS は照合時に0を補うので、壊れていてもログインは通る。
> **サーバーはハッシュなので補えない。**壊れたまま切り替えると、その方は入れない。

### ③-2 会員台帳の34列目を作る（**前日までに**）

    LINEユーザーID   ← 2026-09-05 に USER_HEADERS へ追加済み（3a29455・develop）

**予約システムと会員台帳を、同じ方として結ぶための鍵。**
GAS をデプロイすると `ensureUsersSheetStructure_` が列を作る。中身は空のまま。

    clasp push
    clasp deploy -i <デプロイID>        ← **-i を必ず付ける**

当日ではなく**前日までに**済ませる。当日に出すと、列の追加と取り込みが
同じ日に重なり、どちらが原因か切り分けにくくなる。

### ④ 控えを取る

**スプレッドシートのコピーも作る。**（GASは触らないが、戻すときの拠り所）

### ⑤ サーバーが動いていることを、外から確かめる

    curl "https://mayumi-api.tail8efe0d.ts.net/api?action=getNews"

**合鍵なしで通ること。**お客様アプリは合鍵を送らない。

## 2. いつ切り替えるか

# **2026-09-19(土) 10:00 開始**（確定）

```
9/19(土)  ← 開始。この日の診療の予定は無い（院長に確認済み）
9/20(日)  休診
9/21(月)  敬老の日
9/22(火)  国民の休日
9/23(水)  秋分の日 ＋ もともと休診日
9/24(木)  通常診療 再開
```

**当初は「水曜か日曜の深夜2時〜3時」を勧めていた。**端末の記録
（`lastSeenAt`）を93日ぶん数えて、その時間帯が最も静かだったため。

**シルバーウィークはそれより良い。**理由は静かさではなく、**時間**。

| | 深夜2時案 | シルバーウィーク |
|---|---|---|
| 作業できる時間 | 1時間 | **4日半** |
| 不具合に気づく機会 | 翌朝の受付 | 休診中に自分で見つけられる |
| 戻す判断 | その場で即決 | **月曜の夜まで考えられる** |
| 受付への影響 | 翌朝から本番 | 木曜まで無い |

切り替えで最も怖いのは、**戻す判断をする時間が無いこと。**

### 戻す期限を先に決める

**9/21(月) の夜まで。**それまでに不具合が出たら戻す。2日分の記録を
突き合わせるだけで済む。

そこを過ぎたら戻さず、直す方向で進める。日が経つほど、サーバー側に
溜まった記録を書き戻す手間が増えるため。

### 受付が開いている時間には切り替えない

スタンプを入れている最中に切り替わると、記録が片方にしか残らない。
9/19 の午前に予定が無いことは確認済み。

## 3. 切り替えの手順

1. `app.js` の `GAS_URL` を書き換える
2. **ついでに直す（同じ配信なので、ここで一緒に出す）**

   `app.js` のプロフィール保存が `memo: ''` を送っている。
   受け取った側はそれで上書きするので、**お客様が自分の情報を保存するたび、
   受付の覚え書きが消える。**

       await postToGAS({
         type: 'updateUser',
         ...
         memo: '',        ← **この1行を消す**
         ...

   2026-08-23 時点で、メモが入っている方は**0名**。
   すでに全部消えたあとか、そもそも使われていないかのどちらか。
   **直さないと、これから書いても消え続ける。**

   > 送らなければ、サーバーもGASも「いまの値のまま」にする。
   > 消したいときは管理アプリから消す。

3. **`sw.js` のキャッシュ名を上げる**（上げないと古い画面が残る）
4. **`index.html` の `?v=` も上げる**（両方上げないと片方が古いまま）
5. `develop` で確認 → `main` へマージ → push
6. GitHub Pages に出るのを待つ（数分）
7. 自分の端末で開いて、次を確かめる

### 切り替え直後に確かめること

| 見るところ | 期待 |
|---|---|
| お知らせ | 88件出る |
| 商品 | 8件出る |
| カレンダー | 120件出る |
| メニュー | 10件出る |
| スタンプ | **自分の数が変わっていない** |
| 通知の設定 | 入切が変わっていない |
| 「お困りのとき」 | 候補が出る（お名前は伏せ字） |

**スタンプが0になっていたら、すぐ戻す。**

## 4. 戻し方（**何より先に決めておく**）

### 5分で戻る

1. `app.js` の `GAS_URL` を元に戻す
2. `sw.js` と `index.html` の版数を**さらに上げる**（下げない）
3. push → GitHub Pages に出るのを待つ

**版数は下げない。**下げると、新しいほうを掴んだ端末が更新されない。

### 戻したあとに要る作業

切り替えていた間にサーバーへ書かれたぶんは、**スプレッドシートに無い。**

    ・端末の記録合わせ … 消えてよい（次に開けば書き直される）
    ・スタンプの同期   … 消えてよい（端末側にも残っている）
    ・**新規登録**     … **消えてはいけない**
    ・**復元・パスコード再設定** … **消えてはいけない**

戻したら、サーバーの `操作履歴` と `会員` の**行番号が空の行**を見て、
その間に起きたことを手でスプレッドシートへ写す。

    行番号が空 ＝ サーバーが自分で作った記録

**切り替えている時間が短いほど、この作業は軽い。**

## 5. 承知しておくこと

### 合鍵は求めない（GASと同じ）

**お客様アプリは合鍵を1つも送っていない。**GASのWebアプリが
「全員に公開」で動いているため。サーバーも同じ一覧
（`公開アクション`）を持ち、そこに載っているものは通す。

**GASの前にはGoogleの設備があるが、自宅のPCには無い。**
切り替え後しばらくは、当たり方を見張る。

### 入れてある守り

| | |
|---|---|
| 復元の回数制限 | 10回/10分・**お名前ごと**（全体で止めない） |
| 数える場所 | データベース（処理が3つ並んでも効く） |
| パスコード | **ハッシュで保存**（GASは平文） |
| 新規作成 | **お名前が無ければ作らない**（GASは作る） |
| 復元の候補 | 生年月日・電話番号は**返さない**・お名前は伏せる |

### GAS側の穴は塞いだ（2026-08-24・@240）

**`updateUser` は、お名前なしで空の会員を作れた。**合鍵なしで誰でも呼べる。
サーバー側（70d2394）とGAS側（@240）の両方で塞いである。

塞ぐ前に作られた行が残っていないかは、`空の会員を探す()` で見る。

> デプロイは必ず `-i <デプロイID>`。付けないとURLが変わる。
> バージョンが上限200のときの片付け方は[開発者ガイド](../developer_guide.md)。

## 7. 休みのあいだにやること（9/20〜9/23）

切り替えが落ち着いたら、**お客様台帳を1つにまとめる**作業に入る
（院長のご判断・2026-09-05）。会員台帳が既に PostgreSQL にある状態が前提。

### ① ポチコのお客様を、会員台帳に結ぶ

ポチコは LINE のユーザーIDを出してくれない。**表示名で当てる**しかない
（md5/sha1/sha256 を15通り試したが、ハッシュでもなかった）。

    ポチコで予約した方          261名
      表示名が一意に決まる      180名
      うち電話＋氏名でも一致     56名  ← **確実。ここから入れる**
      表示名だけ                残り  ← メモに「表示名で判定」と残す
      友だちにいない             75名  ← ブロック・退会・改名。手が届かない

必要なCSVは2つ。**ポチコを解約すると取り直せない。**先に手元へ落としておく。

    利用者一覧   lineUser-*.csv
    予約一覧     booking-*.csv
      → 期間は URL で指定する。既定は1か月ぶんしか出ない
        https://console.pochico.app/booking?displayDate={"from":"2020-01-01","to":"2026-12-31"}

### ② 予約だけの方の行を作る

    登録経路 = 「予約システム」   ← これで見分ける

**会員数が 162名 → 約360名 に増える。**管理画面の会員一覧の見え方が
変わることを、先に院長へお伝えしてある。

その方々は**アプリにログインできない**（パスワードが無い）。台帳に載るだけ。

### ③ 予約システムが会員台帳を見るようにする

いま予約システムは自前の `Customer` を持っている。**2つ目のお客様台帳を
作らないこと**が、この作業の目的。配線の設計は着手時に決める。

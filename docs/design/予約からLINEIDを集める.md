## いま止まっているところ

```
2. LINEとつなぐ（アプリでIDを集める）  ← これが無いと台帳を引けない
   **2 を飛ばせない。**
```

[LINEとつなぐ](LINEとつなぐ.md) の答えは「アプリで LINE ログインを1回挟む」。
確実で、正しい。**ただしお客様が押してくださらないと、永久に繋がらない。**

```
アプリを開く   →  案内を見る  →  ボタンを押す  →  つながる
                                  ↑ここで止まる方が必ずいる
```

162名のうち何名が押してくださるかは分からない。押さない方は、
予約のたびに「一つの会員情報から拾ってくる」が効かないままになる。

## 予約システムを、集め口にする

**ご予約なさる方は、必ず LINE を通る。**リッチメニューから LIFF で開くため。

```
お客様が LINE から予約する
   ↓
予約システムが受け取るもの
   LINEユーザーID    ← LINE へ問い合わせて確かめた本物（推測ではない）
   お名前・生年月日   ← **ご本人が名乗ったもの**
   ↓
台帳に「その名前＋生年月日」の方が **ちょうど1人** いたら
   ↓
その行の LINEユーザーID を埋める
```

**お客様には何もお願いしない。**予約なさるたびに、勝手に繋がっていく。

### 名前で探すのに、なぜこれは良いのか

CLAUDE.md は「お名前でお客様の記録を探す」を禁じている。この呼び水は
その禁を破っているように見えるが、性質が違う。

```
一括で名寄せする       261名 × 162名 を機械が総当たり
                      間違えたら大量に混ざる。あとから分けられない
                      当てる材料は**表示名**（本名とは限らない）

この呼び水            1人ずつ。ご予約の瞬間だけ
                      材料は**ご本人がその場で入力した本名と生年月日**
                      間違えても1件。しかも次の予約で気づける
```

**生年月日が効いている。**予約システムは生年月日を必須にしてある
（`ReservationForm.birthday`）ので、ほぼ全員に鍵がある。
同姓同名でも生年月日まで一致することは、まずない。

それでも一致したときは、**繋がない**（下記）。

## 歯止め

```
台帳に2人以上当たった    繋がない。件数だけ記録して、院長に決めていただく
台帳に0人               繋がない。台帳に新しい行を作る（窓口②のとおり）
その行にすでにIDがある   触らない。**上書きは絶対にしない**
予約側の生年月日が空     繋がない
台帳側の生年月日が空     当たらない（鍵が作れない）
```

**「分からないままにしておく」ほうが、間違えて繋ぐより安全。**
混ざった記録は、あとから分けられない。

お名前は揃えてから比べる。生のまま比べると
「山田 花子」「山田　花子」「山田花子」が全部別人になる
（予約のたびに空白の有無が変わる。実地で揺れる）。
揃え方は `mayumi-reserve/apps/booking/identity.py`。

## 窓口を1つ足す

[お客様台帳を1つにする](お客様台帳を1つにする.md) の2つに、3つ目を足す。

```
① LINEのIDで会員を探す（読み）      決定済み
② 予約だけの方の行を台帳に作る（書き） 決定済み
③ 会員のLINEIDを埋める（書き）      ← これを足す
```

③ が呼び水。**①が誰も返さない間だけ働き、埋まったら出番が減る。**

送るもの・返るもの:

```
送る   name, kana, birthday, line_user_id
返る   繋いだ会員ID／繋がなかった理由（2人以上・0人・すでにID有り）
```

**書きは失敗したら書かない。**台帳が落ちていても予約は止めない
（[窓口はGASのまま](窓口はGASのまま.md) と同じ考え方）。

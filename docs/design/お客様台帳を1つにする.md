# お客様台帳を1つにする

**2026-09-08。**院長のご要望は2つ。

> お客さんの一元管理をLINEIDを用いて行いたい
> 予約システムの中で予約者の情報を一つの会員情報から拾ってきたい

2026-09-05 に選んでいただいた **A案**（会員台帳を「お客様台帳」に格上げし、
予約だけの方も行を作る）の続き。IDを集める側は [LINEとつなぐ](LINEとつなぐ.md)。

**着手は 9/19 のあと。**

---

## 1つの表にはまとめない

予約システムは**他院に売る前提**で作ってある。

```
mayumi-reserve/docs/design/SaaS化の設計方針.md
  「院に固有の値を、コードに書かない」
  「1か所でも if menu.name == "ビジリス" と書くと、そこが他院で必ず壊れる」
```

まゆみの会員台帳を予約システムから直に読む作り（同じデータベースを見る、
プロジェクトを1つにする）は、**この決めごとを破る。**
他院には会員台帳もスタンプカードもビジリスも無い。

だから **「1つの台帳を、窓口越しに見る」**形にする。
外販をやめて統合する道は、この形からでも後から選べる。逆は選べない。

## 形

```
会員台帳（mayumi-app のサーバー）        ← **正**
    member_id      MYM-####
    line_user_id   ← 結ぶ鍵
    name / kana / phone / birthday / address

予約システム（mayumi-reserve）
    booking.Customer
      line_user_id   同じ鍵
      name/kana/phone   ← **台帳から拾ってきた控え**
    Membership・Ticket・Payment・CareUser は Customer にぶら下がる（今のまま）
```

予約システムの中は**すでに1つ**になっている。回数券も支払いも産後ケアも
`booking.Customer` を指している。**足りないのは台帳との結び目だけ。**

設定を1つ足す。**「会員台帳の窓口」。**
空なら今までどおり自前で持つ（他院）。入っていればそこから拾う（まゆみ）。

## 窓口は2つ

**① LINEのIDで会員を探す（読み）**
LINEログインの直後に呼ぶ。お名前・フリガナ・電話が返る。
**お客様に入力させない。**これが「一つの会員情報から拾ってくる」の中身。

**② 予約だけの方の行を台帳に作る（書き）**
台帳に無ければ作る（登録経路＝予約システム）。A案のとおり。
その方はアプリにログインできない。会員数は 162名 → 約360名 になる見込み。

## 決めごと

**正は台帳。**予約システムでお名前を直したら、台帳へ返す。
2か所で別々に直せるようにすると**正が2つになる。**
お知らせで実際に起きた（本番91件・サーバー88件。2026-09-05）。

**読みが失敗したら控えを使う。**台帳が落ちていても予約は止めない。
GASからサーバーへ渡すときと同じ考え方（[窓口はGASのまま](窓口はGASのまま.md)）。
**書きは失敗したら書かない。**正が2つになるのを防ぐ。

**LINEIDで探す。お名前で探さない。**
同姓同名・改名・表記ゆれで別の方に行き着く。
`Member` にも `booking.Customer` にも、すでにそう書いてある。

## 順番

```
1. 9/19  会員をサーバーへ移す
2.       LINEとつなぐ（アプリでIDを集める）  ← これが無いと台帳を引けない
3.       予約システムが台帳を見る
```

**2 を飛ばせない。**台帳の line_user_id が空のままでは、①の窓口が誰も返さない。

## ポチコ移行への効き目

[ポチコの顧客を結ぶ] の計画は**表示名で当てる**方法で、261名中131名しか
結べない見込みだった。CLAUDE.md が禁じている「お名前でお客様を探す」に近い。

お客様ご自身にアプリでLINEをつないでいただければ、**その作業自体が要らなくなる。**
9/19 の移行では、ポチコ分を急いで突き合わせず**待つ**という選び方ができる。

## 確かめること

- **予約システムがいま何名のお客様を持っているか。**教室4件を公開済みなので
  実データがある。台帳と突き合わせる作業が要る（LINEIDで突き合う）。
- 同じLINEが2人の会員に付いていないか。`Member.line_user_id` は unique なので
  台帳側は弾けるが、**弾いたときお客様に何と出すか**が未決。

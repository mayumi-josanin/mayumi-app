進め方の全体像は [窓口はGASのまま](窓口はGASのまま.md)。

## 移す前に、必ず数える6つ

推測で進めて、**6回とも取りこぼした。**すべて本番前に見つかったが、
1つでも見落とせばお客様の画面に出ていた。

### ① 同じ名前の関数が複数ないか

```
grep -c "^function 名前(" gas/管理者・お客様.js
```

**JavaScript は後の定義が前を上書きする。**`getBlogNews` と `getAdminBlogs` が
2か所ずつあり、**効かないほう（5000行）を読んで返す形を決めてしまった。**
6項目足りず、管理画面でリンクも画像も並び順も消えるところだった。

| 表 | 同名の関数 |
|---|---|
| お知らせ | `getBlogNews` `getAdminBlogs` |
| カレンダー | `getAdminCalendar` `getCalendarEvents` |
| 商品・メニュー・FAQ・カテゴリ | 無し |

### ② その窓口は表をまたがないか

```
data.sheet === 'BLOG' / 'PRODUCTS' / 'CALENDAR' / 'MENUS' / 'PUSH' / 'SURVEYS'
```

を**機械的に数える。名前の印象で判断しない。**
`handleUpdateNoticeVisibility` と `handleDeleteNoticeListing` を
「Notice と付いているからお知らせ専用」と思い込み、無条件に転送した。
**ショップの項目を一覧から削除しようとして失敗した。**

またぐ窓口は5つ。

```
handleUpdateRecordStatus  handleUpdateNoticeVisibility  handleDeleteNoticeListing
handleDeleteRow           handleDeleteRows
```

### ③ 保存以外に何をしているか

| 処理 | 早い return で飛ぶか |
|---|---|
| **通知（sendAutoPush）** | **飛ぶ。**ハンドラの中にある |
| キャッシュ破棄 | 飛ばない。`doPost` の側（2979行） |
| 監査ログ | 飛ばない。`doPost` の側（2981行） |

`handleAddBlog` で**通知だけが消えていた。**書いたあとに呼び直す形に直した。
判断に使う状態は**サーバーが書いたあとに返す**（GASはもうシートを読めない）。

### ④ 入口ではなく大元で渡す

| 大元 | 呼び出し元 |
|---|---|
| `getSupportFaqEntries_` | getSupportFaq / getAdminSupportFaq / **askSupportChat** |
| `getCategories` | doGet / getBlogNews / getInitialData / getAdminBlogs |

入口2つに入れて済ませかけ、**チャットボットだけがシートを読み続ける**ところだった。

### ⑤ その応答に、他の表が相乗りしていないか

`getNews` は**カテゴリの一覧も一緒に返す。**お知らせを移した時点で、
カテゴリの食い違いが生まれていた。院長がカテゴリを足しても出ない。

**1つ移すと、相乗りしている表も道連れになる。**

### ⑥ サーバー側に、同じ処理の関数が既にないか

`views.py` に `_画像()` が**あったのに**、`_お知らせ()` だけが自前に1行書いていた。
シートは画像URLを JSON の配列の文字列で持つので、**91件中82件で画像が壊れた。**
カテゴリでも同じことをしていた（重複除去と種別の検証を通していなかった）。

**書く前に探す。**

## 決めごと

| | |
|---|---|
| **読み**が失敗したら | シートに落ちる。真っ白より古い中身のほうが害が小さい |
| **書き**が失敗したら | **シートに書かない。**その場でエラー。落ちる先を作ると正が2つになる |
| `notImplemented` | **成功として扱わない。**書けていないのに書けたことになる |
| 削除の作法 | **表ごとに違う。サーバー側でそろえない** |
| 見た目 | **変えない。**日時の書式もボタンの出方も今のまま |

削除の作法の実際:

```
お知らせ  印を付けるだけ（行は残る）
FAQ      本当に消し、下の行番号を繰り上げる（行番号で指されるため）
カテゴリ  本当に消す。繰り上げない（名前で指されるので番号は誰も見ていない）
```

## 手順

1. **数える**（上の6つ）
2. サーバー側に窓口を作る
3. **本番と全項目を突き合わせる。**件数が合っているだけでは足りない
   （お知らせは数が合ったあとに、画像・ボタン・時刻の3つが違っていた）
4. **定義の順序を機械で確かめる。**使う場所より後ろに定義を置いて、
   **起動はするが最初の通信で落ちる**状態を作った。`docker compose ps` は正常に見える
5. GAS に転送を入れる（大元1か所・保存以外の処理を残す）
6. `clasp push` → `clasp deploy -i <デプロイID>`
7. **`SERVER_TABLES` に表の名前を足す** ← ここが切り替えの瞬間
8. 本番で読み書きを1件ずつ確かめる

**戻すのは `SERVER_TABLES` から名前を消すだけ。デプロイは要らない。**

## ⑦ その列は、書き出しに定義されているか（2026-09-05 追加）

カレンダーの**カテゴリ70件が、まるごと落ちていた。**

    書き出し   `掲載書出_カレンダーの列` に `category` が無い
    モデル     `category` の列が無い
    取り込み   運んでいない
    読み出し   `"category": ""` を固定で返していた

**4か所すべてに無い**という揃った抜けだったので、コードを読んでも
「そもそも無いもの」に見えた。**本番と突き合わせて初めて出た。**

同じ形で、メニューの登録日13件も落ちていた（日付の書き方が読めず、
取り込みが黙って None にしていた）。

**書き出しに無い列は、どこまで行っても現れない。**
移す表ごとに、**GAS が `ensureNamedColumn_` で拾っている列**を数え、
書き出しの定義と突き合わせる。

## ⑧ 型まで合っているか

    "costPrice": "1875.000000"    ← Decimal をそのまま JSON にすると**文字列**

GAS は `Number(...)` で数を期待している。**目で見ると同じに見える。**
突き合わせでは `repr()` で比べる。

似た例:

    stockQty          Number(row[9]  || 0)  → 欄に文字が入ると NaN → **null**
    lowStockThreshold Number(row[10] || 0)  → 欄は数字か空 → **0**

**式が同じでも、入っている値が違えば結果は違う。**

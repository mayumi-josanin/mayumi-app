# Git 運用ルール

> 編集から公開までの手順は **[開発者ガイド](developer_guide.md)** にまとめています。
> このページはブランチの役割とルールだけを扱います。

## ブランチの役割

```
main      ← 本番。お客様が見る画面        push すると即座に公開される
 ↑ merge
develop   ← ふだんの作業場所              確認用サーバーで見る
```

| ブランチ | 反映先 | 見る方法 |
|---------|--------|---------|
| `develop` | どこにも自動反映されない | 手元で確認用サーバーを立てる |
| `main` | **GitHub Pages（本番）** | https://mayumi-josanin.github.io/mayumi-app/ |

**編集は必ず `develop` で行います。**

## 絶対にやらないこと

```bash
git push origin main    # ❌ 確認なしにお客様の画面が変わる
git push --force        # ❌ 履歴が消える
```

`main` へは、確認が済んでから `develop` をマージして出します。

## main へ出すまでの順番

**この順番でないと、動かない場所へお客様をご案内してしまいます。**

1. `develop` で作業し、確認用サーバーで動作を確認する
2. **ログインが要る部分は院長に確認していただく**（開発側では確認できない）
3. `develop` → `main` をマージして push
4. 公開URLで動作を確認する
5. [お客様へのお知らせ](お客様へのお知らせ.md)を掲載する
6. ビジリスの旧URLに転送ページを設置する（`bijiris/_移転用/` を参照）

## バックエンド（GAS）は別勘定

**GAS はブランチと無関係です。**`clasp push` した時点で本番のコードが変わります。

| | 反映のタイミング |
|---|---|
| 画面（HTML/JS/CSS） | `main` に push したとき |
| GAS のトリガー処理 | **`clasp push` した瞬間**（Head で動くため） |
| GAS の Webアプリ | **`clasp deploy` したとき** |

つまり「develop で作業中」でも、GAS を push すると本番の自動処理が変わります。
GAS を触るときは、それが本番への変更だと意識してください。

## コミットメッセージ

日本語で、**何をしたか**を書きます。`種類(場所): 内容` の形は使っていません。

```
入り口: パスコード未設定の方への案内を追加し、登録のお願いを一覧の前に出す
回数券の自動処理: 回答が増えていなければ即座に抜ける（4.1秒→0.4秒）
```

## 確認コマンド

```bash
git branch --show-current                  # 今どのブランチにいる？
git status --short                         # 未コミットの変更は？
git log --oneline main..develop            # 本番に未反映の変更
git diff --stat main..develop              # その変更でどのファイルが変わるか
```

**push する前に1行目を確認する癖をつけてください。**
